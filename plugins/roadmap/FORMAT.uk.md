# Формат дошки «Роадмап» (t510)

Переклад `FORMAT.md` українською (t1428). Ця дошка — українська: у шапці паспорта `lang: uk`, слова формату — українські (розділ «Мова дошки»).
Дошка проєкту — звичайні текстові файли в папці `<проєкт>\.kermach\roadmap\`.
Їх читають і правлять руками в редакторі, агент пише їх напряму, програма показує їх на панелі.
Зразки всіх видів файлів — у папці `samples.uk\` поруч із цим описом.

## Папка

Усі файли лежать просто в `.kermach\roadmap\`, без підпапок.

| Файл | Що це | Скільки |
|---|---|---|
| `passport.md` | паспорт проєкту | один |
| `f<N>.md` | фаза, наприклад `f1.md` | по файлу на фазу |
| `t<N>.md` | картка, наприклад `t12.md` | по файлу на картку |
| `d<N>.md` | рішення, глухий кут, домовленість або патерн, наприклад `d3.md` | по файлу на запис |
| `counter.json` | лічильник номерів | один |

Огляд проєкту — `.kermach\обзор.md`, поруч із папкою дошки, а не в ній: що агент з'ясував про проєкт перед складанням роадмапу, у кожного факту джерело. Ім'я файлу `обзор.md` лишається російським: його шукає програма. Сама програма огляд не читає.

Правила імен:
- `<N>` — лише цифри. `t09.md` і `t9.md` — це один номер 9; два такі файли одночасно — помилка в обох.
- Інші імена в папці (`README.md`, `t12.bak`, `картка.md`, підпапки) — помилка «невірне ім'я».
  Файл із помилкою програма не показує й не править, решта читаються.
- Імена з крапкою на початку (`.t12.md.tmp`) і з `~` у кінці — службові файли редакторів, програма їх мовчки пропускає.
- Файл більший за 256 КБ — помилка «завеликий», програма його не читає.

## Як улаштований файл

Усі `.md` улаштовані однаково:

```
---
ключ: значення
ключ: значення
---
# Заголовок
Тіло
```

Шапка — між двома рядками `---` на самому початку файлу.
У шапці кожен рядок — `ключ: значення`. Ключі латиницею, значення — мовою дошки (тут — українською, див. «Мова дошки»).
Порожнє значення — нічого після двокрапки. Список — у квадратних дужках через кому: `depends: [t09, t10]`.
Свої ключі можна додавати: програма їх не чіпає й зберігає під час правки.
Рядок шапки без двокрапки або без закривної `---` — помилка «зламана шапка».

Після шапки — заголовок `# …` і тіло. Рядок `# …` усередині блоку коду ```…``` — не заголовок.
Літера «ё» в значеннях російською необов'язкова: «ждет ответа» читається як «ждёт ответа».
Закінчення рядків (LF або CRLF) програма зберігає такими, якими знайшла.

Деякі слова програма читає лише російською — на українській дошці пиши їх саме так, російською:
- значення `effort` (`высокое` та інші з таблиці картки), `advisor: да`, `draft: да`, `pick: человек`;
- у паспорті `card_mcp: все` / `никаких`, `card_skills` і `card_check` — `да` / `нет`; у записі `pattern: нет`;
- рядки тексту `Текст ошибки:`, `Неверно (tN): …`, `Проверено человеком (…)`, назва «Правило работы: …», рядки патерна `Правило:`, `Почему:`, `Когда не так:`;
- заголовки розділів `## Переносимый вывод`, `## Ответ человека (…)`, `## Вопрос`, рядок `Стек:` у паспорті.

## Картка — `t<N>.md`

Шапка:

| Ключ | Що це | Значення |
|---|---|---|
| `id` | номер, збігається з іменем файлу | `t12` |
| `phase` | фаза | номер фази `f1`; порожньо — картка у «Вхідних» |
| `status` | статус | `в черзі`, `в роботі`, `чекає відповіді`, `на перевірці`, `на рев'ю`, `пауза`, `готово` |
| `kind` | вид роботи, за ним береться шаблон промпту | `зробити`, `рев'ю`, `розвідка`; немає ключа — `зробити` |
| `agent` | хто робить | `claude`, `codex` або ім'я свого агента |
| `model` | модель | будь-яка, наприклад `opus`, `gpt-5.5`; порожньо — типова для агента. Списки у вікні — `agents.js` |
| `effort` | зусилля, необов'язково | будь-яке, наприклад `высокое` (російською: так його читає `agents.js`); порожньо — типове. Вікно знає `минимальное`, `низкое`, `среднее`, `высокое`, `очень высокое`, `максимальное` |
| `advisor` | чи кликати радника, необов'язково | `да` — у завдання картки йде рядок «поклич радника», лише у виконавця `claude`; немає ключа або інше — не йде. Модель радника програма не ставить: вона береться з налаштувань Claude (`advisorModel` у `~\.claude\settings.json`); там її немає — агент скаже, що радника немає, і зробить картку без нього |
| `pick` | хто вибрав модель і зусилля, необов'язково | `человек` — їх назвала людина, повторна спроба їх не підвищує; немає ключа — вибрав той, хто заводив картку, за правилом нижче |
| `agent_why` | чому такі агент, модель, зусилля й радник, необов'язково | один рядок, наприклад `розвідка — sonnet низкое` |
| `checked` | підсумок перевіряльника картки, пише програма | один рядок, наприклад `выполнено, круг 1: 4 из 4 критериев` або `нужна доработка, круг 2 из 3: нет пробы для выкл`; повний розбір — `.kermach/grades/tN-круг.md` (t1330) |
| `tries` | номер спроби запуску, пише програма (t1440) | число `1`, `2`, `3`…; переписується під час кожного запуску із «Запустити», `kermach roadmap run`, хвилі й пачки. У готової картки — з якої спроби її здано: за ним `kermach roadmap accept fN` зводить яруси `size.js`. Руками не правити; немає ключа — картку запускали до t1440 або не програмою |
| `depends` | від яких карток залежить | список номерів `[t09, t10]` або порожньо |
| `human` | чи потрібна людина | `без людини`, `потрібна людина` |
| `draft` | чернетка, необов'язково (t1325) | `да` — картка дальньої фази без «Як перевірити»: хвиля «Усі» й «Незалежні» її пропускає з причиною «чернетка», «Виділені» запускають; у рядку картки на панелі позначка «чернетка». Немає ключа — звичайна картка. Нижче — «Чернетка картки» |
| `created` | коли завели | `2026-10-12 11:20` |
| `closed` | коли закрили, необов'язково | `2026-10-12 15:40`; ставить агент під час закриття, вікно — під час зміни статусу на «готово». Немає ключа — у промпт сусідньої картки фази (частина 5) ця картка потрапить, лише якщо заведена пізніше (`created`), а рядок картки на дошці — без часу: час файлу після `git clone` невірний |
| `source` | хто завів, необов'язково | `знайшов claude у сесії t15`, `додала людина` |
| `served` | які записи програма подала агентові в завданні; пише програма під час запуску картки, агент не чіпає | `[d12, d40]`; повторний запуск дописує нові номери, попередні лишаються |
| `from` | з якої справи «Справ» картка; пишуть `kermach tasks card kN` і кнопка «В роадмап проєкту» (t1163). Картку закрили — справа позначається зробленою сама | `k12` |
| `used` | відгук агента про записи, які допомогли, необов'язково; пише агент під час закриття | `помогла: d12 — знайшов ту саму причину зависання; помогла: d40 — взяв готову команду проби` (t1433); слово `помогла:` — російською, його читає програма; у старих карток — `d12 помогла, d40 не пригодилась, d77 неверна, d81 не открывал`; шматок не за зразком — зауваження дошки, картка читається |

Обов'язкові `id` і `status`, решту можна не писати.

Хто заводить картку, той вибирає їй агента і, якщо хоче, модель, зусилля й радника.
Агент — `claude`, якщо людина не назвала іншого виконавця.
Модель і зусилля — перший відповідний рядок згори:
1. Людина сама назвала модель або зусилля — став їх, у будь-якого виконавця, і `pick: человек`.
2. Виконавець не `claude` (codex та інші) — `model` і `effort` порожні.
3. Інакше `model` і `effort` не пиши: ярус рахує програма під час запуску за текстом картки (`size.js`, рішення t1045) і пише причину в журнал плагіна та в рядок «наступний запуск» вікна. Картку з порожніми полями «Що зробити», «Файли» і «Як перевірити» вона вважає ярусом opus: мало даних — ярус вищий.

| Ярус | Модель і зусилля | Коли |
|---|---|---|
| opus | `opus`, `низкое` | прод або незворотне; причина невідома або поведінка плаваюча; жести, фокус, порядок подій, час; архітектура, протокол, демон; 4 і більше файлів у `src`; перевірка з 4 і більше пунктів; правка кількох файлів `src` без точних місць |
| sonnet | `sonnet`, `низкое`, радник один раз перед здачею | решта: розвідка й рев'ю без правки `src`; текст, перевірки, проби без `src`; правка `src` у відомому місці (файл:рядок) |
| haiku | `haiku` | лише за словом людини (`pick: человек`): заголовок із дієслова навігації — знайти, зібрати, перенести, перейменувати, заміряти, порахувати — і `src` не чіпається. Програма сама haiku не ставить, лише підказує в журналі |

Радник ставиться окремо від моделі й лише виконавцеві `claude`. Картці ярусу sonnet програма дає рядок «поклич радника один раз перед здачею» сама (t1042: без радника Sonnet здав приховану помилку в 4 прогонах із 4, з радником — 0 із 4). `advisor: да` пиши для проду, грошей, незворотного і коли радника просить людина: тоді рядок «до першої правки й перед закриттям», за будь-якої моделі. У codex та інших виконавців радника немає — ключа `advisor` не став; програма рядок радника їм і не дає.
Повторна спроба після «чекає відповіді» — щаблем вище по драбині `sonnet низкое → opus низкое → opus среднее`; картка з `pick: человек` не підвищується.
Причину вибору пиши одним рядком в `agent_why`, коли модель вибрала людина або оркестратор: що сказано й чому.

Повторна спроба. Картку запускають знову після «чекає відповіді» (червона перевірка, питання, агент зупинився без «готово») — програма бере щабель вище: `sonnet низкое` → `opus низкое` → `opus среднее` (`LADDER` в `agents.js`).
У файлі картки `model` і `effort` не змінюються: щабель іде лише в аргументи вкладки, рядок про нього — у журналі плагіна. Не підвищується картка з `pick: человек`, не claude і з моделлю чи зусиллям не з цієї драбини.
Як рахуються спроби:
- спроба дійшла до «чекає відповіді» — наступний запуск щаблем вище. Неважливо, хто поставив цей статус: агент, програма за вкладкою чи людина у вікні;
- людина відповіла в тій самій вкладці, і агент знову «в роботі» — це та сама спроба, позначка «дійшла до відповіді» знімається;
- вкладку закрили посеред роботи («пауза»), картка пішла «на перевірку» або «на рев'ю» — лік не змінюється;
- картка стала «готово» або її повернули «в чергу» — лік починається заново.
`pick: человек` програма ставить сама, коли людина змінює у вікні модель або зусилля на непорожні. Скидання моделі під час зміни агента `pick` не ставить.

Тіло: заголовок `# …` — назва картки. Нижче — підписані рядки.

Назва — для людини. Людина з однієї назви розуміє, що зміниться після картки: що запрацює інакше або що з'явиться.
Простими словами, до ~80 знаків. Без внутрішніх імен — функцій, файлів, змінних, ключів, номерів проб — і без жаргону: вони — у «Що зробити».
Погано → добре:
- «"не открывал" у --used — четвертий вердикт для звірки t1329» → «Звірка точніше рахує користь нотаток: агент позначає, які не відкривав»;
- «Проби: підсумок дочірнього процесу за exit, а не за close» → «Перевірки не гублять вивід програми під навантаженням»;
- «Гейт у 2–3 потоки: перевірки без вікна паралельно» → «Гейт швидший: перевірки без вікна йдуть по три одразу».
Підпис — на початку рядка, із двокрапкою; текст іде після двокрапки й може тривати на наступних рядках.
Поле закінчується на наступному підписі зі списку, на порожньому рядку або на заголовку.
Блок коду ```…``` — частина поля як є: порожній рядок, `#` і підпис усередині блоку поле не закінчують. Блок починається з нового рядка після підпису.

| Підпис | Ключ у програмі |
|---|---|
| `Що зробити:` | `what` |
| `Навіщо:` | `why` |
| `Файли:` | `files` |
| `Як перевірити:` | `check` |
| `Особливі вказівки:` | `notes` |
| `Що зроблено:` | `done` |
| `Доказ:` | `proof` |

«Як перевірити» — команда й очікуваний підсумок, якщо потрібно щось понад перевірку проєкту з паспорта.
«Як перевірити» міряє мету картки, а не лише відсутність помилок (t1434). Мета — збіг зі зразком (верстка, макет, дизайн, старий сайт) — перевірка звіряє з ним усю сторінку згори донизу: кожна секція зразка є на сторінці або прибрана за відповіддю людини.
«Відкривається без помилки», «без fatal», «один H1» такій картці замало: перевіряльник поверне її з підсумком «критерії не підходять». Погано → добре: «головна відкривається без fatal, один H1» → «головна відкривається без fatal; секції згори донизу збігаються з html/index.html: 12 із 12, знімок усієї сторінки поруч зі знімком зразка».
«Що зроблено» і «Доказ» заповнюються під час закриття; доказ — вивід команди, коміт або файл і рядок.
Порожнє поле — прочерк `—` або нічого.
Свій текст пишіть після порожнього рядка: тоді він не стане частиною поля, і програма його не зачепить.

```
---
id: t12
phase: f1
status: в черзі
agent: codex
depends: [t09]
human: без людини
---
# Кошик: перерахунок доставки
Що зробити: під час зміни міста в кошику доставка перераховується без перезавантаження.
Навіщо: зараз ціна доставки відстає на один крок, покупці йдуть (скарга 09.10).
Файли: `theme/js/cart.js`, `inc/shipping.php`.
Як перевірити: `remote-check.sh` зелений; руками — змінити місто, ціна змінюється одразу.
Особливі вказівки: не чіпати `theme/js/city.js`.
Що зроблено: —
Доказ: —
```

### Відповідь людини (t1354)
Відповідь на питання агента — розділ у кінці картки. Його пише програма, а не руками:
- головна сесія або людина в терміналі — `kermach roadmap answer tN "текст"` (або `-`: текст зі стандартного вводу);
- панель «Роадмап» — команда плагіна `answer`.

Заголовок розділу — російський, `## Ответ человека (…)`: за ним програма знаходить відповідь.

```
## Ответ человека (26.10 22:40)
варіант 1: перевіряльник вірить лише відповідям, записаним програмою.
```

Розділ закінчується на наступному заголовку або підписі поля. У тексті не можна починати рядок із `#`, ```` ``` ```` або підпису поля: команда відмовить.
Разом із розділом програма записує відбиток тексту (sha1 проєкту, номера картки й тексту) в `answers.json` у папці даних Kermach (`%APPDATA%\Kermach\plugins-data\roadmap\`), а не в папці проєкту.
Перевіряльник картки (`card_check`) бачить лише відповіді з відбитком. Розділ, який вписали в картку руками, і рядки на кшталт «Ответ оркестратора …» — не відповідь для перевіряльника: критерій вони не знімають. Агентові картки їх і далі видно в промпті.
Правка тексту розділу після запису, перенесення в іншу картку чи перейменування папки проєкту — відбиток не збігнеться, відповідь треба записати заново.
З вкладки агента картки (`KERMACH_CARD` в оточенні) команда `answer` відмовляє з кодом 5: відповідь людини агент сам собі не пише.
Це захист від помилки агента, а не від обману. Агент працює під тим самим користувачем Windows, що й програма: прибрати `KERMACH_CARD` з оточення чи записати `answers.json` сам він може. Замка через головний процес немає навмисно: запис файлу в папці даних він однаково не закриває.

### Чернетка картки (t1325)
Роадмап пишеться заздалегідь повністю: перша фаза — повними картками, решта — чернетками. Чернетка — картка з `draft: да` у шапці й `status: в черзі`.
У ній заголовок, «Що зробити», «Навіщо», «Файли»; «Як перевірити» порожнє або прочерк. Подробиці й «Як перевірити» дописують на звірці після попередньої фази: за тим, що дізналися в роботі.
Дописали — ключ `draft` прибирають із шапки, і картка стає звичайною. Хвиля бере її лише після цього: агент не отримує картку без «Як перевірити».
Чому поле, а не статус. Чернетка — це «в черзі, але не розписана». Новий статус довелося б навчити всіх, хто читає статус: лік карток фази, звіт фази, `kermach roadmap`, переклади, правку у вікні. Поле бачать лише хвиля й рядок картки на панелі.

### Картка-рев'ю фази (t1325)
Остання картка кожної фази — `kind: рев'ю`, `depends` — усі інші картки фази. Свіжий агент перевіряє, як зійшлася робота сусідніх карток.
«Як перевірити» у неї — кожна ознака готовності фази по пунктах: так чи ні і чим доведено (команда, файл і рядок, сторінка). У фазі-чернетці рев'ю — теж чернетка.
Ознаки виписують словами, а не посиланням «за кожною ознакою фази»: перевірка роадмапу шукає в «Як перевірити» слова кожної ознаки.

### Перевірка роадмапу (t1437)
Програма перевіряє дошку без ШІ: `kermach roadmap check [fN]` (без fN — незакінчені фази; помилки є — код 4).
Та сама перевірка йде сама у двох місцях: коли будівник записав картки й викликав `kermach roadmap start --summary` (підсумок — у його вивід, у завдання головної сесії й рядком під фазою) і перед запуском хвилі фази.
Що вважається помилкою:
- фаза без картки `kind: рев'ю` або без ознак готовності;
- картка фази без «Як перевірити» або без «Файли» (порожньо чи прочерк). Чернетка (`draft: да`) і картка «готово» не рахуються;
- картка-рев'ю, у «Як перевірити» якої немає ознак фази: ознаку знайдено, коли в тексті є хоча б половина її слів;
- `depends` на картку, якої немає на дошці;
- кільце залежностей: t1 чекає на t2, а t2 чекає на t1 (або довше; картка, яка чекає сама на себе, — теж кільце).
Знайшлися помилки — хвиля фази не стартує: під фазою рядок «Хвилю не запущено: перевірка роадмапу знайшла помилки» зі списком.
Запустити з ними — лише людина, кнопкою «запускати попри все» в тому самому рядку. `kermach roadmap wave fN` у цьому разі відповідає кодом 4 і перелічує помилки.
Хвиля «Виділені» перевіряє лише виділені картки: рев'ю й ознаки фази їй не потрібні. Продовження перерваної хвилі не перевіряє: її вже запускали.
Виправили картки — рядок зникає сам під час наступного читання дошки.

### Свіжий перевіряльник роадмапу (t1438)
Програма ловить помилки форми. Помилки змісту — картка не рухає ознаку фази, перевірка міряє не мету — ловить свіжий агент: будівник свої помилки бачить погано.
Коли: будівник викликав `kermach roadmap start --summary`, перевірка програмою помилок не знайшла, а вкладка будівника жива. `start` із термінала людини, без вкладки будівника, відкриває головну сесію одразу, як раніше.
Хто: окремий `claude -p`, модель opus, зусилля «високе», лише читання (Read, Glob, Grep). Завдання — шаблон `review-roadmap.md` поруч із цим файлом (українською — `review-roadmap.uk.md`), своя копія — у папці даних плагіна, як у `compose.md`.
Що перевіряє:
- у кожної картки є ознака готовності її фази — поле «Навіщо» називає її; у кожної ознаки є картка;
- ознаку видно на ділі: вивід команди, сторінка, файл; «усі картки закрито» — не ознака;
- «Як перевірити» міряє мету картки, а не «відкривається без помилки»;
- є зразок — перша фаза закінчується пілотом зі звіркою сторінки повністю, у кожної фази зі сторінками є ознака звірки зі зразком;
- секції зразка без даних: відповідь людини записано в огляді до того, як заведено картки цих сторінок;
- порядок фаз і залежності, картка доступу в карток із сервером.

Кіл не більше двох:
- поки коло йде, `start` відповідає кодом 4 і текстом «проверка роадмапа идёт» (перевірка роадмапу триває) — вкладку головної сесії не відкрито;
- підсумок кола програма друкує у вкладку будівника одним рядком «[Роадмап] Проверка роадмапа, круг N из 2: …» (перевірка роадмапу, коло N із 2) зі шляхом до розбору. Рядок не дійшов (людина довго набирає текст, вкладка не прийняла) — наступний `start` віддає його відповіддю, наступне коло не починає;
- серйозні зауваження — будівник править дошку й викликає `start` ще раз: друге коло;
- чисто, друге коло скінчилося або перевірки не відбулося (ліміт, немає claude, довше 20 хвилин) — наступний `start` відкриває головну сесію. Що лишилося й чому перевірки не було — у її завданні: вона скаже людині.
Серйозне — картка без ознаки фази, ознака без картки, ознака «усі картки закрито», перевірка не тієї мети, немає пілота чи звірки зі зразком, секція без відповіді людини, немає потрібної залежності. Решта — дрібне, людині в підсумку.
Розбір кожного кола — `.kermach\grades\roadmap-N.md` у папці проєкту (наступний вільний номер, не для git). Коло пам'ятає програма: перевідкриття вікна не починає перевірку заново, нова вкладка будівника — починає з кола 1.
Перевіряльник займає одне з двох місць перевіряльників карток: за двох перевірок карток, що йдуть, він чекає своєї черги.

Хвиля не запускає разом дві картки зі спільним файлом. Спільний файл — один шлях у «Файлах» обох карток, однакове ім'я файлу або папка, у якій лежить файл іншої картки.
Друга картка чекає з позначкою «чекає файл: tNN», поки перша працює, чекає відповіді, на перевірці або на рев'ю; запускається, коли перша стала «готово» і її перевірка скінчилася.
Тримає файл і картка, яку запустили не хвилею.

### Свіжий перевіряльник фази (t1439)
Дальні фази пишуться чернетками й дописуються після попередньої фази, а на її прийманні людина вносить правки. Перевірка роадмапу на початку цього не бачить. Тому перед запуском фази її перевіряє той самий свіжий агент — лише за цією фазою.
Коли: перша хвиля фази (`kermach roadmap wave fN` або кнопка хвилі «Усі» чи «Незалежні»), якщо перевірка програмою помилок не знайшла, попередня фаза скінчилася — `status: готова` або всі її картки «готово», — а в цій фазі жодну картку ще не запускали (усі «в черзі» або «пауза»).
Першу фазу не перевіряє: її перевірив перевіряльник роадмапу. «Виділені» і «запускати попри все» — рішення людини, перевірки немає.
Хто: той самий `claude -p`, що й у роадмапу. Завдання — розділ «## Проверка фазы» у `review-roadmap.md` (заголовок російською й у перекладі: за ним програма знаходить розділ); у своїй копії цього розділу немає — береться вбудований.
Що перевіряє:
- чернеток (`draft: да`) у фазі немає: хвиля мовчки пропустила б їх;
- у кожної картки є «Як перевірити», і воно міряє мету картки;
- правки людини з приймання попередньої фази дійшли до карток: головна сесія пише їх у «Зараз» рядком «Правки приёмки для fN: …»;
- ознаки фази покривають картки й навпаки, остання картка — рев'ю;
- картки не спираються на те, чого попередня фаза не зробила.

Порядок той самий, що в роадмапу, лише вкладка — головної сесії, а команда — `wave`:
- поки коло йде, `wave` відповідає кодом 4 і текстом «проверка фазы идёт» (перевірка фази триває) — хвилі немає;
- підсумок кола — рядком «[Роадмап] Проверка фазы fN, круг K из 2: …» у вкладку головної сесії. Рядок із зауваженнями або про збій не дійшов — наступний `wave` віддає його відповіддю;
- серйозні зауваження — головна сесія править картки й викликає `wave` ще раз: друге коло;
- чисто, друге коло скінчилося або перевірки не відбулося — наступний `wave` запускає хвилю. Що лишилося після другого кола, головна сесія показує людині до запуску.
Розбір кожного кола — `.kermach\grades\phase-fN-K.md`. Коло пам'ятає програма: перевідкриття вікна не починає перевірку заново.

## Фаза — `f<N>.md`

Фази йдуть за порядком номерів: `f1`, `f2`, …

| Ключ | Що це | Значення |
|---|---|---|
| `id` | номер, збігається з іменем файлу | `f1` |
| `status` | статус | `запланована`, `триває`, `готова` |
| `health` | здоров'я | `зелений`, `жовтий`, `червоний` або порожньо |
| `health_why` | один рядок, чому таке здоров'я | текст |
| `health_by` | хто поставив | `людина`, `codex` |
| `health_at` | коли | `2026-10-11 14:02` |

Обов'язкові `id` і `status`.
Тіло: `# …` — назва фази. Підпис `Мета:` — мета фази.
Підпис `Ознаки готовності:` — нижче список, по ознаці на рядок: `- [ ] …` не позначена, `- [x] …` позначена.
Рядок `- [ ]` усередині блоку коду ```…``` — приклад, а не ознака: вікно його не показує й клацанням не змінює.
Фаза готова, коли позначено всі ознаки, а не коли скінчилися картки.
Є зразок (верстка, макет, дизайн, старий сайт) — у першої фази й у кожної наступної, яка змінює сторінки, ознака «сторінки фази збігаються зі зразком по всій сторінці: кожна секція є або прибрана за відповіддю людини» (t1434). Звірку не відкладають в останню фазу й не обмежують першим екраном.

```
---
id: f1
status: триває
health: зелений
health_why: перевірка зелена, закриті картки без повернень
health_by: людина
health_at: 2026-10-11 14:02
---
# Кошик
Мета: покупець збирає замовлення й бачить чесну ціну з доставкою до оплати.
Ознаки готовності:
- [x] Місто вибирається й зберігається в кошику
- [ ] Доставка перераховується під час зміни міста
```

## Паспорт — `passport.md`

Постійна частина про проєкт, одна на всі картки. У шапці — мова дошки (`lang: uk`, розділ «Мова дошки») і, за бажанням, налаштування старту агента картки (t1322):

```
---
lang: uk
card_mcp: никаких
card_skills: нет
---
```

| Ключ | Значення | Що робить |
|---|---|---|
| `card_mcp` | `все` · `никаких` · імена через кому: `playwright, context7` | MCP-сервери агента картки. `никаких` — прапорець claude `--strict-mcp-config`. Список — лише ці сервери: програма сама пише їхній файл із налаштувань Claude (`.claude.json` і `.mcp.json` проєкту) і передає його `--mcp-config`; файл видаляється, коли вкладка агента вийшла. Сервери з плагінів Claude і конектори claude.ai у списку не знайти — картка з ними не запуститься: для них `все`. |
| `card_skills` | `да` · `нет` | `нет` — скіли й команди «/» вимкнено: прапорець claude `--disable-slash-commands`. |
| `card_check` | `да` · `нет` | Перевіряльник картки (t1330). `да` — картку, закриту агентом із «Запустити», перевіряє окремий `claude -p` (sonnet, низьке, лише читання): бачить «Що зробити», «Як перевірити» і зміни від початку картки, розмову агента не бачить. Підсумок — рядок `checked:` у картці. «Потрібна доробка» — зауваження йдуть у вкладку агента, картка знову «в роботі», не більше 3 кіл, після третього — «чекає відповіді». «Критерії не підходять» — «чекає відповіді». Картки виду `рев'ю` і `розвідка` без команди в «Як перевірити» не перевіряються. |

Значення цих трьох ключів — російською, як у таблиці: так їх читає програма.
Ключа немає — `все` і `да`, як було до t1322 (у `card_check` — `да`: перевірку ввімкнено). Невірне значення не діє, вікно й журнал «Роадмапу» про нього попереджають.
Субагенти агентові картки заборонені завжди, налаштування для них немає: claude запускається з `--disallowedTools=Agent`.
Прапорці є лише в claude; у codex та інших агентів налаштування не діє, журнал пише про це рядок.
Тіло — дев'ять розділів, у кожного заголовок `## `. У розділах — посилання на файли проєкту, а не переказ.
Порожній розділ — заголовок без тексту; програма покаже його як «порожньо».

| Заголовок розділу | Ключ у програмі |
|---|---|
| `## Транспорт і сервер` | `transport` |
| `## Інструменти проєкту` | `tools` |
| `## Команда перевірки й очікуваний підсумок` | `check` |
| `## Кеш після правки` | `cache` |
| `## Обрив з'єднання` | `disconnect` |
| `## Де зразки й канон` | `samples` |
| `## Що не чіпати` | `keep` |
| `## Що ще має бути, крім зеленої перевірки` | `required` |
| `## Журнал` | `journal` |

Номер перед назвою дозволено: `## 3. Команда перевірки й очікуваний підсумок`. Двокрапку в кінці теж: `## Журнал:`. Регістр літер не важливий. Російські заголовки (`## Транспорт и сервер`) програма теж читає.
Рядки всередині блоку коду ```…``` — текст розділу: `## …` і `# …` там не заголовки. Незакритий ``` блоком не вважається.
Поодинока ``` бере в пару найближчу ``` нижче, як у Markdown, і розділи між ними стають текстом блоку. Вікно про такий розділ попереджає, а «Зберегти» його не пише, поки блок у файлі не закрито.
Розділ зі своїм заголовком зберігається як є.

## Рішення, глухий кут, домовленість або патерн — `d<N>.md`

| Ключ | Що це | Значення |
|---|---|---|
| `id` | номер, збігається з іменем файлу | `d3` |
| `type` | вид запису | `рішення`, `глухий кут`, `домовленість` — домовленість із людиною або правило роботи для всіх карток (чим правити файли, як запускати), затверджене людиною; `патерн` — одне правило, узагальнення 3+ записів про одну причину; `нотатка` — знахідка збоку, яка не заважає зараз (t1046): агентам не подається, у патерни не йде, картку з неї заводить людина |
| `card` | картка, на якій знайшли | `t12` або порожньо |
| `files` | яких файлів стосується | список `[src/cart/delivery.ts]` |
| `date` | коли | `2026-10-12` |
| `agent` | хто записав | `codex`, `людина` |
| `how` | наскільки надійно | `перевірено` — підтверджено прогоном, `здогадка` — ні; або порожньо |
| `until` | термін придатності: останній день, коли запис діє | `2026-12-31` або порожньо — безстроково |
| `repeats` | картки, де ту саму причину знайшли знову | список `[t40, t55]` або порожньо |
| `cancelled` | дата скасування: запис більше не діє, але лишається в історії | `2026-10-15` або порожньо |
| `differs` | записи, на які цей не схожий: людина натиснула «не схоже» біля позначки «схожа на dN», позначку цієї пари вікно більше не ставить | список `[d32]` або порожньо |
| `wrong` | картки, чий агент позначив запис «невірний» | список `[t901]` або порожньо; до кожної — рядок `Неверно (t901): чому` у тексті (слово `Неверно` — російською), без нього позначка не діє (зауваження дошки) |
| `stack` | чий код винен: тема, плагін, бібліотека | список `[woocommerce, woodmart@8.1]` або порожньо: ім'я в нижньому регістрі (a-z, цифри, `.` `-` `_` `/`, `@scope/` на початку), версія через `@` за бажанням |
| `from` | у патерна: з яких записів зібраний | список `[d77, d97, d136]` |
| `approved` | у патерна: день, коли людина його затвердила | `2026-10-16` або порожньо — чекає затвердження |
| `pattern` | людина сказала «не патерн»: запис більше не пропонується зібрати в патерн | `нет` (російською) або порожньо |
| `for` | у домовленості: кому вона (t1433) | `агент` — правило роботи агента картки; `програма` — для програми й оркестратора (яку модель запускати, як вести дошку): агентові картки не подається; порожньо — агентові |

Обов'язкові `id` і `type`. Порожнє значення — те саме, що ключа немає: записи без нових ключів читаються як раніше.
Невірне значення — помилка файлу, як у картки: `how` не зі списку, `until` чи `cancelled` не справжня дата `РРРР-ММ-ДД`, у `repeats` і `wrong` не `t<номер>`, у `differs` і `from` не `d<номер>`, `approved` не дата, `pattern` не `нет`, `for` не `агент` і не `програма`.
Агентові картки програма не подає запис із `cancelled`, запис `type: нотатка`, домовленість із `for: програма` і запис, у якого `until` раніше за сьогодні; `until` сьогоднішнім днем ще діє.
Нотатка — знахідка для людини: вона чекає у «Вхідних» вікна «Роадмап», картку з неї заводить людина; у промпт картки й у `kermach roadmap notes` вона не йде.
Запис із `wrong` (і рядком «Неверно (tN): …») агентам теж не подається, поки людина його не подивиться: список — `kermach roadmap notes --wrong`. Запис вірний — людина очищає `wrong`, рядок «Неверно…» лишається історією; невірний — ставить `cancelled` (t836).
Людина подивилася й вирішила, що запис вірний, — рядок «Неверно (tN): …» стає «Проверено человеком (РРРР-ММ-ДД): верна, отзыв tN снят» (так пише програма, російською), tN іде з `wrong`, і запис знову подається. Об'єднання переносить `wrong` повтору в старий запис разом із його рядками «Неверно».
Закриваючи картку, агент пише в її шапку `used:` — лише записи, які допомогли, і чим (t1433): `помогла: d12 — знайшов ту саму причину зависання; помогла: d40 — взяв готову команду проби`. Частини — через `;`; усе після тире — пояснення, номери в ньому відгуком не вважаються. «Чим» — не менше двох слів від трьох літер, крім номерів і слів «помогла», «пригодилась»: `kermach roadmap close` без нього відмовляє з кодом 1 і пише, як треба. Записи, що не допомогли, агент не перелічує; жоден не допоміг — `used` немає.
Старі картки з `d12 помогла, d40 не пригодилась, d77 неверна, d81 не открывал` читаються як раніше, без зауваження: сувора перевірка — лише під час закриття. Запис виявився невірним — це позначка `wrong` у шапці запису, а не відгук.
Промпт картки, частина 5 «Нотатки до задачі» (до t1433 записи йшли у двох частинах: 5 «Свіже» — рішення й глухі кути за датою, і 6). За порядком: домовленості агентові — кожній картці, повним текстом, без відбору за файлами й датою; затверджені патерни; до 5 рішень і глухих кутів за словами й файлами картки; закриті після картки картки цієї фази й «Вхідні» за тими самими файлами — рядками. Відбору рішень за датою більше немає: свіжий запис про іншу частину програми агентові не допомагає (ЗАМЕЧАНИЯ-роадмапа.md, розділ З).
Рішення й глухі кути — до 6 з усіх чинних за словами й файлами картки: спершу збіг із текстом помилки в картці, потім слова в назві запису, потім слова його тексту, потім спільні файли; здогадка нижче за перевірений, запис із `repeats` вище. Записів більше — останній рядок «Показано 5 записей из M»: решту агент шукає в папці дошки сам. Тому текст помилки й точні слова в картці й у назві запису допомагають знайти його потім.
Той самий підбір за текстом помилки, а не за карткою, — команда `kermach roadmap notes "текст помилки"`: агент кличе її, коли помилка вилізла в роботі. Тому в записі стоїть дослівний текст помилки або симптом, як його видно до розбору, а не лише причина.
Тіло: `# …` — тема. Нижче — суть вільним текстом: причина → що зробили (у глухого кута — що пробували й чому не вийшло).
У рішення й глухого кута — рядок `Текст ошибки:` (підпис російською: за ним програма шукає симптом): дослівно, як симптом видно до розбору (повідомлення, рядок журналу, що на екрані). Помилки не було — `Текст ошибки: —`. Новий запис без тексту отримує цей рядок із `—`: агент замінює прочерк.
Помилка вилізла знову з тією самою причиною — нового запису немає: агент дописує свою картку в `repeats` старого, а симптом повтору — ще одним рядком `Текст ошибки: … (t<номер>)` одразу під `# …`. Під заголовком, а не в кінці: у підборі агентові видно перші 400 знаків тексту. Команда notes читає весь текст, їй місце рядка не важливе; `repeats` піднімає запис вище за рівних збігів (t933).
Причина в чужому коді — у шапці `stack`, у кінці тіла розділ `## Переносимый вывод` (заголовок російською: за ним програма знаходить розділ): що знадобиться в іншому проєкті з тим самим стеком, без адрес, шляхів сервера, імен клієнтів і ключів. Розділ іде до наступного `#`/`##` або кінця файлу; у текст запису для підбору й схожості він не входить. `stack` із великою літерою, пробілом чи кирилицею — помилка файлу. Об'єднання (`об'єднати`) дописує розділ повтору в розділ старого запису, а імена `stack`, яких у старого немає, — у його `stack`.
Спільна база на всі проєкти (t844) — папка `known\` у папці даних плагіна (`%APPDATA%\Kermach\plugins-data\roadmap\known\`). Збирання промпту саме копіює туди рішення чи глухий кут із `how: перевірено`, `stack` і розділом «Переносимый вывод» — файлом `s<N>.md`: заголовок, `type`, `stack`, перший рядок `Текст ошибки:` і розділ. Рядки «<заголовок> (dN):» після об'єднання не копіюються. Текст запису, `files`, `card` та ім'я проєкту в базу не йдуть; звідки запис — у `known\state.json`.
Не йдуть: здогадка, скасований і прострочений запис, позначений «невірний», «Правило работы: …», запис без `stack` або розділу. Розділ з адресою сайту, IP, поштою, шляхом з іменем користувача, шляхом чи іменем папки проєкту, схожим на ключ, — теж: запис лишається в проєкті з позначкою причини, нічого не вирізається. `s<N>.md` можна правити руками: програма його більше не перезаписує; видалили — не повертає. Файл із мітками конфлікту git агентові не подається.
Частина 6 після своїх записів — до 3 записів бази з інших проєктів: `stack` перетинається з рядком `Стек: ім'я, ім'я` у розділі «Інструменти проєкту» паспорта (слово `Стек:` — російською, так його шукає програма) або зі `stack` своїх записів (версії не важливі), або `Текст ошибки:` запису є в тексті картки. Зведення бази — `known\known.md`, рядок на запис.
Патерн іде в базу так само — `s<N>.md` з `type: патерн`, але лише затверджений людиною (`approved:` і відбиток в approved.json), `how` йому не потрібен. Поправили після затвердження — копія знімається з бази до нового затвердження. В іншому проєкті патерн подається лише за `stack`, не за текстом помилки, і першим серед записів бази. Своєму агентові розділ «Переносимый вывод» не подається — ні в частині 5 промпту, ні в `kermach roadmap notes` (t992): текст запису несе ту саму причину й виправлення словами цього проєкту, точніше за узагальнення, а розділ з'їв би частину 400 знаків, які запис отримує в підборі. Розділ — для інших проєктів; агент бачить його, коли відкриває `d<N>.md`.

# Зона доставки
Текст ошибки: Delivery zone is undefined
Зону беремо з міста в кошику, а не з профілю: профіль може бути порожнім.

Патерн (t845). Програма помічає кандидата: запис, на який схожі ще 2+ записи (позначка «схожа на dN» або `repeats`), або 3+ записи з одним `Текст ошибки:`. Текст патерна пише агент за карткою «Зібрати патерн»: один запис `type: патерн`, `from` — номери записів, заголовок — правило одним рядком, тіло — `Правило:`, `Почему:`, `Когда не так:` (підписи російською), усього не більше 400 знаків. `approved` агент не ставить: затверджує людина кнопкою, програма пам'ятає sha1 затвердженого тексту у своїй папці даних. Шлях проєкту в затвердження не входить (t1018): перейменування папки його не знімає, а той самий текст патерна в іншому проєкті затверджений одразу й там. Правка тексту після затвердження — патерн знову чекає людину. `from` з номером запису, якого немає, — зауваження дошки.
Відбиток рахується від заголовка, тексту, «Переносимого вывода» і `from`, без шапки: кнопка сама пише в шапку `approved:`. Тому правка `files`, `stack`, `card`, `how` затвердження не знімає — правило від них не змінюється.
У вікні, вкладка «Рішення, тупики, домовленості», фільтр «патерни» (t1005): у кандидата — «схоже на патерн: d77 і ще 5» і кнопки «зібрати в патерн» (картка «Зібрати патерн з d77, …» у «Вхідних») і «не патерн» (`pattern: нет` у шапці d77); у патерна — «чекає затвердження» і кнопка «затвердити». Позначку «схожа на dN» патерн не отримує й сам не дає: «об'єднати» видалило б патерн або дописало б у нього текст. «Об'єднати» (t1014): патерн об'єднується лише з патерном, `from` старого — обидва списки разом. Запис із `from` об'єднали з іншим — у `from` патернів його номер замінюється номером старого. `from` змінився — затвердження знято, патерн знову чекає людину.

## Мова дошки — `lang:` у паспорті (t1429)

Статуси, види, підписи полів і розділи паспорта можна писати однією з чотирьох мов: `ru`, `uk`, `en`, `de`.
Мова дошки — рядок `lang:` у шапці `passport.md`. У цієї дошки:

```
---
lang: uk
---
```

Рядка немає, паспорта немає або значення незнайоме — дошка російська. Так працюють усі дошки, заведені до t1429.
«Скласти роадмап» ставить `lang:` за мовою вікна Kermach, коли агент заведе паспорт; російській мові рядок не потрібен.

Як програма читає:
- значення шапки (`status`, `kind`, `human`, у фази `status` і `health`, у запису `type` і `how`) — будь-якою з чотирьох мов. Агент написав `status: done` на українській дошці — картка однаково «готово»;
- підписи полів картки й фази (`Що зробити:`) і заголовки розділів паспорта — російською й мовою дошки. Підпис іншої мови — звичайний текст: рядок «Why: …» в українській картці не стає полем «Навіщо»;
- регістр, «ё» і вид апострофа (`'`, `’`, `ʼ`) не важливі.

Як програма пише: нові значення шапки й нові підписи — мовою дошки. Підписи, які вже є у файлі, вона не змінює.

Змінити мову — «Мова дошки» у вікні паспорта. Програма переписує слова формату в усіх файлах дошки.
Перед записом — бекап: усі файли дошки копіюються в `.kermach\roadmap-backup-РРРРММДД-ГГХХСС\`, поруч із папкою дошки.
Якщо хоч один файл новою мовою прочитався б інакше, мова не змінюється зовсім і жоден файл не зачеплено: наприклад, рядок тексту починається зі слова, яке новою мовою — підпис поля. Файл із помилкою розбору й файл, який правили під час зміни, не зачіпаються, вікно їх називає.

## Лічильник — `counter.json`

```
{ "t": 18, "d": 3 }
```

`t` — останній виданий номер картки, `d` — останній номер запису рішень.
Номер спільний на проєкт і дається одразу, коли картка з'явилася, зокрема у «Вхідних». Під час перенесення у фазу він не змінюється.

Нова картка чи запис — командою в терміналі Kermach: `kermach roadmap new t "Заголовок"` або `kermach roadmap new d "Суть" --card t12`. Номер видає програма: два агенти разом не візьмуть один номер.
Поля картки — прапорцями: `--text` — «Що зробити», `--why` — «Навіщо», `--files` — «Файли», `--check` — «Як перевірити» (t1439). Перевірку пишіть у `--check`, а не в `--text`: інакше «Як перевірити» лишиться порожнім, і перевірка роадмапу не дасть запустити хвилю. Картка у фазі без `--check` — зауваження у виводі команди.

Нова картка руками:
1. Знайдіть найбільший номер — у `counter.json` і серед файлів `t<N>.md`.
2. Новий номер — на один більший. Запишіть його в `counter.json`.
3. Створіть файл `t<номер>.md`, у шапці `id` з тим самим номером.

Номер видаленої картки повторно не видається. Лічильника немає — програма рахує його за файлами.
