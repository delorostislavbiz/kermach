# Промпт карты: общие правила и шаблоны видов работы

Из этого файла программа собирает части 1 и 3 промпта карты (t514). Он один на все проекты.
Файл читается заново при каждом показе промпта: правка видна в следующем промпте без перезапуска программы.

Где править. Этот файл рядом с кодом плагина — встроенный текст: обновление программы его перезаписывает.
Править нужно копию в папке данных плагина: `%APPDATA%\TERMINALUS\plugins-data\roadmap\prompt.md`.
Копия есть — программа берёт её. Копии нет — берёт этот встроенный текст. Обновление программы копию не трогает.

Как устроено:
- текст до первого заголовка `## ` — это пояснение для человека, в промпт он не идёт;
- `## Общие правила` — часть 1, одна на все карты;
- `## Шаблон: сделать`, `## Шаблон: ревью`, `## Шаблон: разведка` — часть 3, по полю `kind` карты (нет поля — «сделать»);
- в тексте можно писать подстановки: `{папка}` — папка доски этого проекта, `{образец}` — образец файла карты, `{карта}` — номер карты.

Предел попыток на красной проверке сюда не пишется: это настройка волны.

## Общие правила
Ты работаешь над одной картой роадмапа: {карта}. Делай то, что написано в карте, и не больше.
Доска проекта — текстовые файлы в папке {папка}. Карта — файл t<номер>.md, решение или тупик — d<номер>.md. Пиши в эти файлы напрямую.
Закрой карту так: в её файле поставь `status: готово` и `closed: ГГГГ-ММ-ДД ЧЧ:ММ` (сейчас), заполни «Что сделано:» и «Доказательство:» — вывод команды проверки, коммит или файл и строку.
«Готово» — только когда команда проверки из паспорта прошла. Без прогона карту не закрывай.
Копай вбок: заметил рядом ошибку того же рода — проверь, если это несколько минут чтения. Найденное сбоку не чини сам.
Каждую находку запиши новой картой во «Входящие»: файл карты без `phase`. Номер — следующий после самого большого в counter.json и среди файлов t<номер>.md; запиши его и в counter.json.
Нужен ответ человека — поставь карте `status: ждёт ответа` и задай вопрос с вариантами. Первым всегда вариант, который ты рекомендуешь, и почему.
Нашёл неочевидную причину или тупик — запиши файлом d<номер>.md: поля type, card, files, date, agent; ниже суть.
Образец файла карты:
{образец}

## Шаблон: сделать
Порядок: прочитай файлы из поля «Файлы» → напиши план в три строки → правь → запусти команду проверки из паспорта и из поля «Как проверить» → закрой карту.

## Шаблон: ревью
Порядок: прочитай изменения по файлам карты (дифф или файлы целиком) → сверь их с полями «Что сделать» и «Как проверить» → запиши замечания в «Что сделано» списком: место (файл:строка) и почему это ошибка.
Сам код не правь. Ошибку, которую надо чинить, оформи картой во «Входящие».

## Шаблон: разведка
Порядок: выясни то, что спрашивает карта, читая код и документы проекта → ничего в проекте не меняй → ответ запиши в «Что сделано»: вывод одной-двумя фразами и на чём он основан (файл:строка, вывод команды).
Чего не выяснил — так и напиши, с причиной.
