# Формат доски «Роадмап» (t510)

Доска проекта — обычные текстовые файлы в папке `<проект>\.kermach\roadmap\`.
Их читают и правят руками в редакторе, агент пишет их напрямую, программа показывает их в панели.
Образцы всех видов файлов — в папке `samples\` рядом с этим описанием.

## Папка

Все файлы лежат прямо в `.kermach\roadmap\`, без подпапок.

| Файл | Что это | Сколько |
|---|---|---|
| `passport.md` | паспорт проекта | один |
| `f<N>.md` | фаза, например `f1.md` | по файлу на фазу |
| `t<N>.md` | карта, например `t12.md` | по файлу на карту |
| `d<N>.md` | решение, тупик, договорённость или паттерн, например `d3.md` | по файлу на запись |
| `counter.json` | счётчик номеров | один |

Обзор проекта — `.kermach\обзор.md`, рядом с папкой доски, а не в ней: что агент выяснил о проекте перед составлением роадмапа, у каждого факта источник. Программа его не читает.

Правила имён:
- `<N>` — только цифры. `t09.md` и `t9.md` — это один номер 9; два таких файла сразу — ошибка у обоих.
- Другие имена в папке (`README.md`, `t12.bak`, `карта.md`, подпапки) — ошибка «неверное имя».
  Файл с ошибкой программа не показывает и не правит, остальные читаются.
- Имена с точкой в начале (`.t12.md.tmp`) и с `~` в конце — служебные файлы редакторов, программа их пропускает молча.
- Файл больше 256 КБ — ошибка «слишком большой», программа его не читает.

## Как устроен файл

Все `.md` устроены одинаково:

```
---
ключ: значение
ключ: значение
---
# Заголовок
Тело
```

Шапка — между двумя строками `---` в самом начале файла.
В шапке каждая строка — `ключ: значение`. Ключи латиницей, значения — на языке доски (по умолчанию по-русски, см. «Язык доски»).
Пустое значение — ничего после двоеточия. Список — в квадратных скобках через запятую: `depends: [t09, t10]`.
Свои ключи можно добавлять: программа их не трогает и сохраняет при правке.
Строка шапки без двоеточия или без закрывающей `---` — ошибка «сломанная шапка».

После шапки — заголовок `# …` и тело. Строка `# …` внутри блока кода ```…``` — не заголовок.
Буква «ё» в значениях необязательна: «ждет ответа» читается как «ждёт ответа».
Окончания строк (LF или CRLF) программа сохраняет такими, какими нашла.

## Карта — `t<N>.md`

Шапка:

| Ключ | Что это | Значения |
|---|---|---|
| `id` | номер, совпадает с именем файла | `t12` |
| `phase` | фаза | номер фазы `f1`; пусто — карта во «Входящих» |
| `status` | статус | `в очереди`, `в работе`, `ждёт ответа`, `на проверке`, `на ревью`, `пауза`, `готово` |
| `kind` | вид работы, по нему берётся шаблон промпта | `сделать`, `ревью`, `разведка`; нет ключа — `сделать` |
| `agent` | кто делает | `claude`, `codex` или имя своего агента |
| `model` | модель | любое, например `opus`, `gpt-5.5`; пусто — по умолчанию агента. Списки в окне — `agents.js` |
| `effort` | усилие, необязательно | любое, например `высокое`; пусто — по умолчанию. Окно знает `минимальное`, `низкое`, `среднее`, `высокое`, `очень высокое`, `максимальное` |
| `advisor` | звать ли советника, необязательно | `да` — в задание карты идёт строка «позови советника», только у исполнителя `claude`; нет ключа или другое — не идёт. Модель советника программа не ставит: она берётся из настроек Claude (`advisorModel` в `~\.claude\settings.json`); там её нет — агент скажет, что советника нет, и сделает карту без него |
| `pick` | кто выбрал модель и усилие, необязательно | `человек` — их назвал человек, повторная попытка их не повышает; нет ключа — выбрал тот, кто заводил карту, по правилу ниже |
| `agent_why` | почему такие агент, модель, усилие и советник, необязательно | одна строка, например `разведка — sonnet низкое` |
| `checked` | итог проверяющего карты, пишет программа | одна строка, например `выполнено, круг 1: 4 из 4 критериев` или `нужна доработка, круг 2 из 3: нет пробы для выкл`; полный разбор — `.kermach/grades/tN-круг.md` (t1330) |
| `tries` | номер попытки запуска, пишет программа (t1440) | число `1`, `2`, `3`…; переписывается при каждом запуске из «Запустить», `kermach roadmap run`, волны и пачки. У готовой карты — с какой попытки она сдана: по нему `kermach roadmap accept fN` сводит ярусы `size.js`. Руками не править; нет ключа — карту запускали до t1440 или не программой |
| `depends` | от каких карт зависит | список номеров `[t09, t10]` или пусто |
| `human` | нужен ли человек | `без человека`, `нужен человек` |
| `draft` | черновик, необязательно (t1325) | `да` — карта дальней фазы без «Как проверить»: волна «все» и «независимые» её пропускает с причиной «черновик», «выделенные» запускают; в строке карты на панели пометка «черновик». Нет ключа — обычная карта. Ниже — «Черновик карты» |
| `created` | когда завели | `2026-10-12 11:20` |
| `closed` | когда закрыли, необязательно | `2026-10-12 15:40`; ставит агент при закрытии, окно — при смене статуса на «готово». Нет ключа — в промпт соседней карты фазы (часть 5) эта карта попадёт, только если заведена позже (`created`), а строка карты на доске — без времени: время файла после `git clone` неверное |
| `source` | кто завёл, необязательно | `нашёл claude в сессии t15`, `добавил человек` |
| `served` | какие записи программа подала агенту в задании; пишет программа при запуске карты, агент не трогает | `[d12, d40]`; повторный запуск дописывает новые номера, прежние остаются |
| `from` | из какого дела «Дел» карта; пишут `kermach tasks card kN` и кнопка «В роадмап проекта» (t1163). Карту закрыли — дело отмечается сделанным само | `k12` |
| `used` | отзыв агента о записях, которые помогли, необязательно; пишет агент при закрытии | `помогла: d12 — нашёл ту же причину зависания; помогла: d40 — взял готовую команду пробы` (t1433); у старых карт — `d12 помогла, d40 не пригодилась, d77 неверна, d81 не открывал`; кусок не по образцу — замечание доски, карта читается |

Обязательны `id` и `status`, остальное можно не писать.

Кто заводит карту, тот выбирает ей агента и, если хочет, модель, усилие и советника.
Агент — `claude`, если человек не назвал другого исполнителя.
Модель и усилие — первая подходящая строка сверху:
1. Человек сам назвал модель или усилие — ставь их, у любого исполнителя, и `pick: человек`.
2. Исполнитель не `claude` (codex и другие) — `model` и `effort` пустые.
3. Иначе `model` и `effort` не пиши: ярус считает программа при запуске по тексту карты (`size.js`, решение t1045) и пишет причину в журнал плагина и в строку «следующий запуск» окна. Карту с пустыми полями «Что сделать», «Файлы» и «Как проверить» она считает ярусом opus: мало данных — ярус выше.

| Ярус | Модель и усилие | Когда |
|---|---|---|
| opus | `opus`, `низкое` | прод или необратимое; причина неизвестна или поведение плавающее; жесты, фокус, порядок событий, время; архитектура, протокол, демон; 4 и больше файлов в `src`; проверка из 4 и больше пунктов; правка нескольких файлов `src` без точных мест |
| sonnet | `sonnet`, `низкое`, советник один раз перед сдачей | остальное: разведка и ревью без правки `src`; текст, проверки, пробы без `src`; правка `src` по известному месту (файл:строка) |
| haiku | `haiku` | только по слову человека (`pick: человек`): заголовок с глагола навигации — найти, собрать, перенести, переименовать, замерить, посчитать — и `src` не трогается. Программа сама haiku не ставит, только подсказывает в журнале |

Советник ставится отдельно от модели и только исполнителю `claude`. У карты яруса sonnet программа даёт строку «позови советника один раз перед сдачей» сама (t1042: без советника Sonnet сдал скрытую ошибку в 4 прогонах из 4, с советником — 0 из 4). `advisor: да` пиши для прода, денег, необратимого и когда советника просит человек: тогда строка «до первой правки и перед закрытием», при любой модели. У codex и других исполнителей советника нет — ключа `advisor` не ставь; программа строку советника им и не даёт.
Повторная попытка после «ждёт ответа» — ступенью выше по лестнице `sonnet низкое → opus низкое → opus среднее`; карта с `pick: человек` не повышается.
Причину выбора пиши одной строкой в `agent_why`, когда модель выбрал человек или оркестратор: что он сказал и почему.

Повторная попытка. Карту запускают снова после «ждёт ответа» (красная проверка, вопрос, агент остановился без «готово») — программа берёт ступень выше: `sonnet низкое` → `opus низкое` → `opus среднее` (`LADDER` в `agents.js`).
В файле карты `model` и `effort` не меняются: ступень идёт только в аргументы вкладки, строка о ней — в журнале плагина. Не повышается карта с `pick: человек`, не claude и с моделью или усилием не из этой лестницы.
Как считаются попытки:
- попытка дошла до «ждёт ответа» — следующий запуск ступенью выше. Неважно, кто поставил этот статус: агент, программа по вкладке или человек в окне;
- человек ответил в той же вкладке, и агент снова «в работе» — это та же попытка, отметка «дошла до ответа» снимается;
- вкладку закрыли посреди работы («пауза»), карта ушла «на проверку» или «на ревью» — счёт не меняется;
- карта стала «готово» или её вернули «в очередь» — счёт начинается заново.
`pick: человек` программа ставит сама, когда человек меняет в окне модель или усилие на непустые. Сброс модели при смене агента `pick` не ставит.

Тело: заголовок `# …` — название карты. Ниже — подписанные строки.

Название — для человека. Человек по одному названию понимает, что изменится после карты: что заработает иначе или что появится.
Простыми словами, до ~80 знаков. Без внутренних имён — функций, файлов, переменных, ключей, номеров проб — и без жаргона: они — в «Что сделать».
Плохо → хорошо:
- «"не открывал" в --used — четвёртый вердикт для сверки t1329» → «Сверка точнее считает пользу заметок: агент отмечает, какие не открывал»;
- «Пробы: итог дочернего процесса по exit, а не по close» → «Проверки не теряют вывод программы под нагрузкой»;
- «Гейт в 2–3 потока: проверки без окна параллельно» → «Гейт быстрее: проверки без окна идут по три сразу».
Подпись — в начале строки, с двоеточием; текст идёт после двоеточия и может продолжаться на следующих строках.
Поле кончается на следующей подписи из списка, на пустой строке или на заголовке.
Блок кода ```…``` — часть поля как есть: пустая строка, `#` и подпись внутри блока поле не кончают. Блок начинается с новой строки после подписи.

| Подпись | Ключ в программе |
|---|---|
| `Что сделать:` | `what` |
| `Зачем:` | `why` |
| `Файлы:` | `files` |
| `Как проверить:` | `check` |
| `Особые указания:` | `notes` |
| `Что сделано:` | `done` |
| `Доказательство:` | `proof` |

«Как проверить» — команда и ожидаемый итог, если нужно что-то сверх проверки проекта из паспорта.
«Как проверить» мерит цель карты, а не только отсутствие ошибок (t1434). Цель — совпадение с образцом (вёрстка, макет, дизайн, старый сайт) — проверка сверяет с ним всю страницу сверху вниз: каждая секция образца есть на странице или убрана по ответу человека.
«Открывается без ошибки», «без fatal», «один H1» такой карте мало: проверяющий вернёт её с итогом «критерии не подходят». Плохо → хорошо: «главная открывается без fatal, один H1» → «главная открывается без fatal; секции сверху вниз совпадают с html/index.html: 12 из 12, снимок всей страницы рядом со снимком образца».
«Что сделано» и «Доказательство» заполняются при закрытии; доказательство — вывод команды, коммит или файл и строка.
Пустое поле — прочерк `—` или ничего.
Свой текст пишите после пустой строки: тогда он не станет частью поля, и программа его не тронет.

```
---
id: t12
phase: f1
status: в очереди
agent: codex
depends: [t09]
human: без человека
---
# Корзина: пересчёт доставки
Что сделать: при смене города в корзине доставка пересчитывается без перезагрузки.
Зачем: сейчас цена доставки отстаёт на один шаг, покупатели уходят (жалоба 09.10).
Файлы: `theme/js/cart.js`, `inc/shipping.php`.
Как проверить: `remote-check.sh` зелёный; руками — сменить город, цена меняется сразу.
Особые указания: не трогать `theme/js/city.js`.
Что сделано: —
Доказательство: —
```

### Ответ человека (t1354)
Ответ на вопрос агента — раздел в конце карты. Его пишет программа, а не руками:
- главная сессия или человек в терминале — `kermach roadmap answer tN "текст"` (или `-`: текст со стандартного ввода);
- панель «Роадмап» — команда плагина `answer`.

```
## Ответ человека (26.10 22:40)
вариант 1: проверяющий верит только ответам, записанным программой.
```

Раздел кончается на следующем заголовке или подписи поля. В тексте нельзя начинать строку с `#`, ```` ``` ```` или подписи поля: команда откажет.
Вместе с разделом программа записывает отпечаток текста (sha1 проекта, номера карты и текста) в `answers.json` в папке данных Kermach (`%APPDATA%\Kermach\plugins-data\roadmap\`), а не в папке проекта.
Проверяющий карты (`card_check`) видит только ответы с отпечатком. Раздел, который вписали в карту руками, и строки вида «Ответ оркестратора …» — не ответ для проверяющего: критерий они не снимают. Агенту карты их по-прежнему видно в промпте.
Правка текста раздела после записи, перенос в другую карту или переименование папки проекта — отпечаток не совпадёт, ответ надо записать заново.
Из вкладки агента карты (`KERMACH_CARD` в окружении) команда `answer` отказывает с кодом 5: ответ человека агент сам себе не пишет.
Это защита от ошибки агента, не от обмана. Агент работает под тем же пользователем Windows, что и программа: убрать `KERMACH_CARD` из окружения или записать `answers.json` сам он может. Замка через главный процесс нет намеренно: запись файла в папке данных он всё равно не закрывает.

### Черновик карты (t1325)
Роадмап пишется заранее целиком: первая фаза — полными картами, остальные — черновиками. Черновик — карта с `draft: да` в шапке и `status: в очереди`.
В нём заголовок, «Что сделать», «Зачем», «Файлы»; «Как проверить» пусто или прочерк. Подробности и «Как проверить» дописывают на сверке после предыдущей фазы: по тому, что узнали в работе.
Дописали — ключ `draft` убирают из шапки, и карта становится обычной. Волна её берёт только после этого: агент не получает карту без «Как проверить».
Почему поле, а не статус. Черновик — это «в очереди, но не расписана». Новый статус пришлось бы учить всем, кто читает статус: счёт карт фазы, отчёт фазы, `kermach roadmap`, переводы, правку в окне. Поле видят только волна и строка карты на панели.

### Карта-ревью фазы (t1325)
Последняя карта каждой фазы — `kind: ревью`, `depends` — все остальные карты фазы. Свежий агент проверяет, как сошлась работа соседних карт.
«Как проверить» у неё — каждый признак готовности фазы по пунктам: да или нет и чем доказано (команда, файл и строка, страница). В фазе-черновике ревью — тоже черновик.
Признаки выписывают словами, а не ссылкой «по каждому признаку фазы»: проверка роадмапа ищет в «Как проверить» слова каждого признака.

### Проверка роадмапа (t1437)
Программа проверяет доску без ИИ: `kermach roadmap check [fN]` (без fN — незаконченные фазы; ошибки есть — код 4).
Та же проверка идёт сама в двух местах: когда построитель записал карты и вызвал `kermach roadmap start --summary` (итог — в его вывод, в задание главной сессии и строкой под фазой) и перед запуском волны фазы.
Что считается ошибкой:
- фаза без карты `kind: ревью` или без признаков готовности;
- карта фазы без «Как проверить» или без «Файлы» (пусто или прочерк). Черновик (`draft: да`) и карта «готово» не в счёт;
- карта-ревью, в «Как проверить» которой нет признаков фазы: признак найден, когда в тексте есть хотя бы половина его слов;
- `depends` на карту, которой нет на доске;
- кольцо зависимостей: t1 ждёт t2, а t2 ждёт t1 (или длиннее; карта, которая ждёт сама себя, — тоже кольцо).
Нашлись ошибки — волна фазы не стартует: под фазой строка «Волна не запущена: проверка роадмапа нашла ошибки» со списком.
Запустить с ними — только человек, кнопкой «запускать всё равно» в той же строке. `kermach roadmap wave fN` в этом случае отвечает кодом 4 и перечисляет ошибки.
Волна «выделенные» проверяет только выделенные карты: ревью и признаки фазы ей не нужны. Продолжение прерванной волны не проверяет: её уже запускали.
Исправили карты — строка уходит сама при следующем чтении доски.

### Свежий проверяющий роадмапа (t1438)
Программа ловит ошибки формы. Ошибки смысла — карта не двигает признак фазы, проверка мерит не цель — ловит свежий агент: построитель свои ошибки видит плохо.
Когда: построитель вызвал `kermach roadmap start --summary`, проверка программой ошибок не нашла, а вкладка построителя жива. `start` из терминала человека, без вкладки построителя, открывает главную сессию сразу, как раньше.
Кто: отдельный `claude -p`, модель opus, усилие «высокое», только чтение (Read, Glob, Grep). Задание — шаблон `review-roadmap.md` рядом с этим файлом, своя копия — в папке данных плагина, как у `compose.md`.
Что проверяет:
- у каждой карты есть признак готовности её фазы — поле «Зачем» называет его; у каждого признака есть карта;
- признак виден на деле: вывод команды, страница, файл; «все карты закрыты» — не признак;
- «Как проверить» мерит цель карты, а не «открывается без ошибки»;
- есть образец — первая фаза кончается пилотом со сверкой страницы целиком, у каждой фазы со страницами есть признак сверки с образцом;
- секции образца без данных: ответ человека записан в обзоре до того, как заведены карты этих страниц;
- порядок фаз и зависимости, карта доступа у карт с сервером.

Кругов не больше двух:
- пока круг идёт, `start` отвечает кодом 4 и текстом «проверка роадмапа идёт» — вкладка главной сессии не открыта;
- итог круга программа печатает во вкладку построителя одной строкой «[Роадмап] Проверка роадмапа, круг N из 2: …» с путём к разбору. Строка не дошла (человек долго набирает текст, вкладка не приняла) — следующий `start` отдаёт её ответом, следующий круг не начинает;
- серьёзные замечания — построитель правит доску и вызывает `start` ещё раз: второй круг;
- чисто, второй круг кончился или проверка не состоялась (лимит, нет claude, дольше 20 минут) — следующий `start` открывает главную сессию. Что осталось и почему проверки не было — в её задании: она скажет человеку.
Серьёзное — карта без признака фазы, признак без карты, признак «все карты закрыты», проверка не той цели, нет пилота или сверки с образцом, секция без ответа человека, нет нужной зависимости. Остальное — мелкое, человеку в итоге.
Разбор каждого круга — `.kermach\grades\roadmap-N.md` в папке проекта (следующий свободный номер, не для git). Круг помнит программа: переоткрытие окна не начинает проверку заново, новая вкладка построителя — начинает с круга 1.
Проверяющий занимает одно из двух мест проверяющих карт: при двух идущих проверках карт он ждёт своей очереди.

Волна не запускает вместе две карты с общим файлом. Общий файл — один путь в «Файлах» обеих карт, совпадающее имя файла или папка, в которой лежит файл другой карты.
Вторая карта ждёт с пометкой «ждёт файл: tNN», пока первая работает, ждёт ответа, на проверке или на ревью; запускается, когда первая стала «готово» и её проверка кончилась.
Держит файл и карта, которую запустили не волной.

### Свежий проверяющий фазы (t1439)
Дальние фазы пишутся черновиками и дописываются после предыдущей фазы, а на её приёмке человек вносит правки. Проверка роадмапа в начале этого не видит. Поэтому перед запуском фазы её проверяет тот же свежий агент — только по этой фазе.
Когда: первая волна фазы (`kermach roadmap wave fN` или кнопка волны «все» или «независимые»), если проверка программой ошибок не нашла, предыдущая фаза кончилась — `status: готова` или все её карты «готово», — а в этой фазе ни одну карту ещё не запускали (все «в очереди» или «пауза»).
Первую фазу не проверяет: её проверил проверяющий роадмапа. «Выделенные» и «запускать всё равно» — решение человека, проверки нет.
Кто: тот же `claude -p`, что у роадмапа. Задание — раздел «## Проверка фазы» в `review-roadmap.md`; в своей копии этого раздела нет — берётся встроенный.
Что проверяет:
- черновиков (`draft: да`) в фазе нет: волна молча пропустила бы их;
- у каждой карты есть «Как проверить», и оно мерит цель карты;
- правки человека с приёмки предыдущей фазы дошли до карт: главная сессия пишет их в «Сейчас» строкой «Правки приёмки для fN: …»;
- признаки фазы покрывают карты и наоборот, последняя карта — ревью;
- карты не опираются на то, чего предыдущая фаза не сделала.

Порядок тот же, что у роадмапа, только вкладка — главной сессии, а команда — `wave`:
- пока круг идёт, `wave` отвечает кодом 4 и текстом «проверка фазы идёт» — волны нет;
- итог круга — строкой «[Роадмап] Проверка фазы fN, круг K из 2: …» во вкладку главной сессии. Строка с замечаниями или о сбое не дошла — следующий `wave` отдаёт её ответом;
- серьёзные замечания — главная сессия правит карты и вызывает `wave` ещё раз: второй круг;
- чисто, второй круг кончился или проверка не состоялась — следующий `wave` запускает волну. Что осталось после второго круга, главная сессия показывает человеку до запуска.
Разбор каждого круга — `.kermach\grades\phase-fN-K.md`. Круг помнит программа: переоткрытие окна не начинает проверку заново.

## Фаза — `f<N>.md`

Фазы идут по порядку номеров: `f1`, `f2`, …

| Ключ | Что это | Значения |
|---|---|---|
| `id` | номер, совпадает с именем файла | `f1` |
| `status` | статус | `запланирована`, `идёт`, `готова` |
| `health` | здоровье | `зелёный`, `жёлтый`, `красный` или пусто |
| `health_why` | одна строка, почему такое здоровье | текст |
| `health_by` | кто поставил | `человек`, `codex` |
| `health_at` | когда | `2026-10-11 14:02` |

Обязательны `id` и `status`.
Тело: `# …` — название фазы. Подпись `Цель:` — цель фазы.
Подпись `Признаки готовности:` — ниже список, по признаку на строку: `- [ ] …` не отмечен, `- [x] …` отмечен.
Строка `- [ ]` внутри блока кода ```…``` — пример, а не признак: окно её не показывает и щелчком не меняет.
Фаза готова, когда отмечены все признаки, а не когда кончились карты.
Есть образец (вёрстка, макет, дизайн, старый сайт) — у первой фазы и у каждой следующей, которая меняет страницы, признак «страницы фазы совпадают с образцом по всей странице: каждая секция есть или убрана по ответу человека» (t1434). Сверку не откладывают в последнюю фазу и не ограничивают первым экраном.

```
---
id: f1
status: идёт
health: зелёный
health_why: проверка зелёная, закрытые карты без возвратов
health_by: человек
health_at: 2026-10-11 14:02
---
# Корзина
Цель: покупатель собирает заказ и видит честную цену с доставкой до оплаты.
Признаки готовности:
- [x] Город выбирается и сохраняется в корзине
- [ ] Доставка пересчитывается при смене города
```

Постоянная часть про проект, одна на все карты. Шапки нет, или в ней только настройка старта агента карты (t1322):

---
card_mcp: никаких
card_skills: нет
---
```

Список — только эти серверы: программа сама пишет их файл из настроек Claude (`.claude.json` и `.mcp.json` проекта) и передаёт его `--mcp-config`; файл удаляется, когда вкладка агента вышла. Серверы из плагинов Claude и коннекторы claude.ai в списке не найти — карта с ними не запустится: для них `все`. |

Итог — строка `checked:` в карте. «Нужна доработка» — замечания уходят во вкладку агента, карта снова «в работе», не больше 3 кругов, после третьего — «ждёт ответа». «Критерии не подходят» — «ждёт ответа». Карты вида `ревью` и `разведка` без команды в «Как проверить» не проверяются. |

Ключа нет — `все` и `да`, как было до t1322 (у `card_check` — `да`: проверка включена). Неверное значение не действует, окно и журнал «Роадмапа» о нём предупреждают.
Субагенты агенту карты запрещены всегда, настройки для них нет: claude запускается с `--disallowedTools=Agent`.
Флаги есть только у claude; у codex и других агентов настройка не действует, журнал пишет об этом строку.
Тело — девять разделов, у каждого заголовок `## `. В разделах — ссылки на файлы проекта, а не пересказ.
Пустой раздел — заголовок без текста; программа покажет его как «пусто».

| Заголовок раздела | Ключ в программе |
|---|---|
| `## Транспорт и сервер` | `transport` |
| `## Инструменты проекта` | `tools` |
| `## Команда проверки и ожидаемый итог` | `check` |
| `## Кэш после правки` | `cache` |
| `## Обрыв соединения` | `disconnect` |
| `## Где образцы и канон` | `samples` |
| `## Что не трогать` | `keep` |
| `## Что ещё обязано быть, кроме зелёной проверки` | `required` |
| `## Журнал` | `journal` |

Номер перед названием разрешён: `## 3. Команда проверки и ожидаемый итог`. Двоеточие в конце тоже: `## Журнал:`. Регистр букв не важен.
Строки внутри блока кода ```…``` — текст раздела: `## …` и `# …` там не заголовки. Незакрытый ``` блоком не считается.
Одиночная ``` берёт в пару ближайшую ``` ниже, как в Markdown, и разделы между ними становятся текстом блока. Окно о таком разделе предупреждает, а «Сохранить» его не пишет, пока блок в файле не закрыт.
Раздел со своим заголовком сохраняется как есть.

## Решение, тупик, договорённость или паттерн — `d<N>.md`

| Ключ | Что это | Значения |
|---|---|---|
| `id` | номер, совпадает с именем файла | `d3` |
| `type` | вид записи | `решение`, `тупик`, `договорённость` — договорённость с человеком или правило работы для всех карт (чем править файлы, как запускать), утверждённое человеком; `паттерн` — одно правило, обобщение 3+ записей об одной причине; `заметка` — находка сбоку, которая не мешает сейчас (t1046): агентам не подаётся, в паттерны не идёт, карту из неё заводит человек |
| `card` | карта, на которой нашли | `t12` или пусто |
| `files` | каких файлов касается | список `[src/cart/delivery.ts]` |
| `date` | когда | `2026-10-12` |
| `agent` | кто записал | `codex`, `человек` |
| `how` | насколько надёжно | `проверено` — подтверждено прогоном, `догадка` — нет; или пусто |
| `until` | срок годности: последний день, когда запись действует | `2026-12-31` или пусто — бессрочно |
| `repeats` | карты, где ту же причину нашли заново | список `[t40, t55]` или пусто |
| `cancelled` | дата отмены: запись больше не действует, но остаётся в истории | `2026-10-15` или пусто |
| `differs` | записи, на которые эта не похожа: человек нажал «не похоже» у пометки «похожа на dN», пометку этой пары окно больше не ставит | список `[d32]` или пусто |
| `wrong` | карты, чей агент отметил запись «неверна» | список `[t901]` или пусто; к каждой — строка `Неверно (t901): почему` в тексте, без неё отметка не действует (замечание доски) |
| `stack` | чей код виноват: тема, плагин, библиотека | список `[woocommerce, woodmart@8.1]` или пусто: имя в нижнем регистре (a-z, цифры, `.` `-` `_` `/`, `@scope/` в начале), версия через `@` по желанию |
| `from` | у паттерна: из каких записей собран | список `[d77, d97, d136]` |
| `approved` | у паттерна: день, когда человек его утвердил | `2026-10-16` или пусто — ждёт утверждения |
| `pattern` | человек сказал «не паттерн»: запись больше не предлагается собрать в паттерн | `нет` или пусто |
| `for` | у договорённости: кому она (t1433) | `агент` — правило работы агента карты; `программа` — для программы и оркестратора (какую модель запускать, как вести доску): агенту карты не подаётся; пусто — агенту |

Обязательны `id` и `type`. Пустое значение — то же, что ключа нет: записи без новых ключей читаются как раньше.
Неверное значение — ошибка файла, как у карты: `how` не из списка, `until` или `cancelled` не настоящая дата `ГГГГ-ММ-ДД`, в `repeats` и `wrong` не `t<номер>`, в `differs` и `from` не `d<номер>`, `approved` не дата, `pattern` не `нет`, `for` не `агент` и не `программа`.
Агенту карты программа не подаёт запись с `cancelled`, запись `type: заметка`, договорённость с `for: программа` и запись, у которой `until` раньше сегодня; `until` сегодняшним днём ещё действует.
Заметка — находка для человека: она ждёт во «Входящих» окна «Роадмап», карту из неё заводит человек; в промпт карты и в `kermach roadmap notes` она не идёт.
Запись с `wrong` (и строкой «Неверно (tN): …») агентам тоже не подаётся, пока человек её не посмотрит: список — `kermach roadmap notes --wrong`. Запись верна — человек очищает `wrong`, строка «Неверно…» остаётся историей; неверна — ставит `cancelled` (t836).
Человек посмотрел и решил, что запись верна, — строка «Неверно (tN): …» становится «Проверено человеком (ГГГГ-ММ-ДД): верна, отзыв tN снят», tN уходит из `wrong`, и запись снова подаётся. Объединение переносит `wrong` повтора в старую запись вместе с его строками «Неверно».
Закрывая карту, агент пишет в её шапку `used:` — только записи, которые помогли, и чем (t1433): `помогла: d12 — нашёл ту же причину зависания; помогла: d40 — взял готовую команду пробы`. Части — через `;`; всё после тире — пояснение, номера в нём отзывом не считаются. «Чем» — не меньше двух слов от трёх букв, кроме номеров и слов «помогла», «пригодилась»: `kermach roadmap close` без него отказывает с кодом 1 и пишет, как надо. Не помогшие записи агент не перечисляет; ни одна не помогла — `used` нет.
Старые карты с `d12 помогла, d40 не пригодилась, d77 неверна, d81 не открывал` читаются как раньше, без замечания: строгая проверка — только при закрытии. Запись оказалась неверной — это отметка `wrong` в шапке записи, а не отзыв.
Промпт карты, часть 5 «Заметки к задаче» (до t1433 записи шли в двух частях: 5 «Свежее» — решения и тупики по дате, и 6). По порядку: договорённости агенту — каждой карте, полным текстом, без отбора по файлам и дате; утверждённые паттерны; до 5 решений и тупиков по словам и файлам карты; закрытые после карты карты этой фазы и «Входящие» по тем же файлам — строками. Отбора решений по дате больше нет: свежая запись о другой части программы агенту не помогает (ЗАМЕЧАНИЯ-роадмапа.md, раздел З).
Решения и тупики — до 6 из всех действующих по словам и файлам карты: сначала совпадение с текстом ошибки в карте, потом слова в названии записи, потом слова её текста, потом общие файлы; догадка ниже проверенной, запись с `repeats` выше. Записей больше — последняя строка «Показано 5 записей из M»: остальные агент ищет в папке доски сам. Поэтому текст ошибки и точные слова в карте и в названии записи помогают найти её потом.
Тот же подбор по тексту ошибки, а не по карте, — команда `kermach roadmap notes "текст ошибки"`: агент зовёт её, когда ошибка вылезла в работе. Поэтому в записи стоит дословный текст ошибки или симптом, как его видно до разбора, а не только причина.
Тело: `# …` — тема. Ниже — суть свободным текстом: причина → что сделали (у тупика — что пробовали и почему не вышло).
У решения и тупика — строка `Текст ошибки:`: дословно, как симптом видно до разбора (сообщение, строка журнала, что на экране). Ошибки не было — `Текст ошибки: —`. Новая запись без текста получает эту строку с `—`: агент заменяет прочерк.
Ошибка вылезла снова с той же причиной — новой записи нет: агент дописывает свою карту в `repeats` старой, а симптом повтора — ещё одной строкой `Текст ошибки: … (t<номер>)` сразу под `# …`. Под заголовком, а не в конце: в подборе агенту видны первые 400 знаков текста. Команда notes читает весь текст, ей место строки не важно; `repeats` поднимает запись выше при равных совпадениях (t933).
Причина в чужом коде — в шапке `stack`, в конце тела раздел `## Переносимый вывод`: что пригодится в другом проекте с тем же стеком, без адресов, путей сервера, имён клиентов и ключей. Раздел идёт до следующего `#`/`##` или конца файла; в текст записи для подбора и похожести он не входит. `stack` с заглавной буквой, пробелом или кириллицей — ошибка файла. Объединение (`объединить`) дописывает раздел повтора в раздел старой записи, а имена `stack`, которых у старой нет, — в её `stack`.
Общая база на все проекты (t844) — папка `known\` в папке данных плагина (`%APPDATA%\Kermach\plugins-data\roadmap\known\`). Сборка промпта сама копирует туда решение или тупик с `how: проверено`, `stack` и разделом «Переносимый вывод» — файлом `s<N>.md`: заголовок, `type`, `stack`, первая строка `Текст ошибки:` и раздел. Строки «<заголовок> (dN):» после объединения не копируются. Текст записи, `files`, `card` и имя проекта в базу не идут; откуда запись — в `known\state.json`.
Не уходят: догадка, отменённая и просроченная запись, отмеченная «неверна», «Правило работы: …», запись без `stack` или раздела. Раздел с адресом сайта, IP, почтой, путём с именем пользователя, путём или именем папки проекта, похожим на ключ — тоже: запись остаётся в проекте с пометкой причины, ничего не вырезается. `s<N>.md` можно править руками: программа его больше не перезаписывает; удалили — не возвращает. Файл с метками конфликта git агенту не подаётся.
Часть 6 после своих записей — до 3 записей базы из других проектов: `stack` пересекается со строкой `Стек: имя, имя` в разделе «Инструменты проекта» паспорта или со `stack` своих записей (версии не важны), или `Текст ошибки:` записи есть в тексте карты. Сводка базы — `known\known.md`, строка на запись.
Паттерн уходит в базу так же — `s<N>.md` с `type: паттерн`, но только утверждённый человеком (`approved:` и отпечаток в approved.json), `how` у него не нужен. Поправили после утверждения — копия снимается из базы до нового утверждения. В другом проекте паттерн подаётся только по `stack`, не по тексту ошибки, и первым среди записей базы. Своему агенту раздел «Переносимый вывод» не подаётся — ни в части 5 промпта, ни в `kermach roadmap notes` (t992): текст записи несёт ту же причину и исправление словами этого проекта, точнее обобщения, а раздел съел бы часть 400 знаков, которые запись получает в подборе. Раздел — для других проектов; агент видит его, когда открывает `d<N>.md`.

Текст ошибки: Delivery zone is undefined
Зона берётся из города в корзине, а не из профиля: профиль может быть пустым.

Правило работы — тоже договорённость. Агент заводит его как `решение` с названием «Правило работы: …» и предлагает человеку; тип меняет человек:

Паттерн (t845). Программа замечает кандидата: запись, на которую похожи ещё 2+ записи (пометка «похожа на dN» или `repeats`), или 3+ записи с одним `Текст ошибки:`. Текст паттерна пишет агент по карте «Собрать паттерн»: одна запись `type: паттерн`, `from` — номера записей, заголовок — правило одной строкой, тело — `Правило:`, `Почему:`, `Когда не так:`, всего не больше 400 знаков. `approved` агент не ставит: утверждает человек кнопкой, программа помнит sha1 утверждённого текста в своей папке данных. Путь проекта в утверждение не входит (t1018): переименование папки его не снимает, а тот же текст паттерна в другом проекте утверждён сразу и там. Правка текста после утверждения — паттерн снова ждёт человека. `from` с номером записи, которой нет, — замечание доски.
Отпечаток считается от заголовка, текста, «Переносимого вывода» и `from`, без шапки: кнопка сама пишет в шапку `approved:`. Поэтому правка `files`, `stack`, `card`, `how` утверждения не снимает — правило от них не меняется.
В окне, вкладка «Решения и тупики», фильтр «паттерны» (t1005): у кандидата — «похоже на паттерн: d77 и ещё 5» и кнопки «собрать в паттерн» (карта «Собрать паттерн из d77, …» во «Входящих») и «не паттерн» (`pattern: нет` в шапке d77); у паттерна — «ждёт утверждения» и кнопка «утвердить». Пометку «похожа на dN» паттерн не получает и сам не даёт: «объединить» удалило бы паттерн или дописало бы в него текст. «Объединить» (t1014): паттерн объединяется только с паттерном, `from` старого — оба списка вместе. Запись из `from` объединили с другой — в `from` паттернов её номер заменяется номером старой. `from` поменялся — утверждение снято, паттерн снова ждёт человека.

```

id: d240
type: паттерн
card: t250
files: []
date: 2026-10-16
agent: claude
how: проверено
from: [d77, d97, d136]
approved:
---
# Скрытое окно Electron отдаёт последний нарисованный кадр
Правило: в скрытом окне снимок, щелчок и движение мыши видят старый кадр — перед ними зовите webContents.invalidate() и ждите кадр.
Почему: скрытое окно не перерисовывается само.
Когда не так: окно на экране.
```

## Язык доски — `lang:` в паспорте (t1429)

Статусы, виды, подписи полей и разделы паспорта можно писать на одном из четырёх языков: `ru`, `uk`, `en`, `de`.
Язык доски — строка `lang:` в шапке `passport.md`:

```
---
lang: uk
---
```

Строки нет, паспорта нет или значение незнакомое — доска русская. Так работают все доски, заведённые до t1429.
«Составить роадмап» ставит `lang:` по языку окна Kermach, когда агент заведёт паспорт; русскому языку строка не нужна.

Как программа читает:
- значения шапки (`status`, `kind`, `human`, у фазы `status` и `health`, у записи `type` и `how`) — на любом из четырёх языков. Агент написал `status: done` на украинской доске — карта всё равно «готово»;
- подписи полей карты и фазы (`Що зробити:`) и заголовки разделов паспорта — по-русски и на языке доски. Подпись другого языка — обычный текст: строка «Why: …» в русской карте не становится полем «Зачем»;
- регистр, «ё» и вид апострофа (`'`, `’`, `ʼ`) не важны.

Как программа пишет: новые значения шапки и новые подписи — на языке доски. Подписи, которые уже есть в файле, она не меняет.

Сменить язык — «Язык доски» в окне паспорта. Программа переписывает слова формата во всех файлах доски.
Перед записью — бэкап: все файлы доски копируются в `.kermach\roadmap-backup-ГГГГММДД-ЧЧММСС\`, рядом с папкой доски.
Если хоть один файл на новом языке прочитался бы иначе, язык не меняется вовсе и ни один файл не тронут: например, строка текста начинается со слова, которое на новом языке — подпись поля. Файл с ошибкой разбора и файл, который правили во время смены, не трогаются, окно их называет.

## Счётчик — `counter.json`

```
{ "t": 18, "d": 3 }
```

`t` — последний выданный номер карты, `d` — последний номер записи решений.
Номер общий на проект и даётся сразу, когда карта появилась, в том числе во «Входящих». При переносе в фазу он не меняется.

Новая карта или запись — командой в терминале Kermach: `kermach roadmap new t "Заголовок"` или `kermach roadmap new d "Суть" --card t12`. Номер выдаёт программа: два агента разом не возьмут один номер.
Поля карты — флагами: `--text` — «Что сделать», `--why` — «Зачем», `--files` — «Файлы», `--check` — «Как проверить» (t1439). Проверку пишите в `--check`, а не в `--text`: иначе «Как проверить» останется пустым, и проверка роадмапа не даст запустить волну. Карта в фазе без `--check` — замечание в выводе команды.

Новая карта руками:
1. Найдите самый большой номер — в `counter.json` и среди файлов `t<N>.md`.
2. Новый номер — на один больше. Запишите его в `counter.json`.
3. Создайте файл `t<номер>.md`, в шапке `id` с тем же номером.

Номер удалённой карты повторно не выдаётся. Счётчика нет — программа считает его по файлам.
